# GLM 5.3 Flash on the v0.5.0 wording (2026-10-02)

Report for the 2026-10-02 GLM 5.3 Flash run against the **v0.5.0 principle
wording** (manifest `principles_commit ff8499c`, the reframe of Clarity,
Atomicity, and Asymmetry): 228 cells = 19 tasks × 3 arms (baseline,
total-programming, ponytail) × 4 repetitions, pi harness
(`--runner pi --provider zai-coding --model-id glm-5.3-flash`), per-cell
wall-time cap 1200 s, workers 1. Fixture, prompts, seeds, and scorers are
identical to the v0.4.0 run (`2026-10-02-glm-flash-complete.md`), so the two
reports are directly comparable.

This is the first full run with the events-capture fix in place from the
start: linear trace growth, zero guard kills, zero timeouts, zero retries.
Delivery is 100% first-attempt in all arms — no timeout ladder was needed.

## Delivery, correctness, safety

| arm | delivered | correct | safe |
|---|---|---|---|
| baseline | 76/76 | 73/76 | 74/76 |
| total-programming | 76/76 | 76/76 | 76/76 |
| ponytail | 76/76 | 75/76 | 75/76 |

Total Programming is the only arm with a perfect correctness and safety
record. The baseline misses are `colorpicker` rep 1 (empty diff) and
`cache` rep 2+3 (delivered, scored as over-engineering). The ponytail miss
is `sql-user` rep 0, which shipped a literal `raise NotImplementedError`
stub — a genuine miss this time, not a scorer artifact (the v0.4.0
`sql-user` miss was the `sqlite3.Row` repr artifact in the baseline arm).

## Tokens and time

| metric (per-task median) | baseline | total-programming | ponytail |
|---|---:|---:|---:|
| tokens | 25,100 | 22,455 | 11,948 |
| wall time | 182.5 s | 145.0 s | 65.0 s |

In v0.4.0 the Total Programming arm cost ~3% *more* tokens than baseline
(23.2k vs 24.0k medians) and was slightly slower. On the v0.5.0 wording the
arm is **~10% below baseline on tokens and ~20% faster**. Observational
(single run, no significance test), but the direction is what the reframe
hopes for: spending care where it matters instead of everywhere.

## Blind readability judge (Sonnet, anonymous A/B, 24 pairs per comparison)

- **total-programming vs baseline: 18–4** (mean 3.88 vs 2.92). One
  Total Programming win is a walkover (`colorpicker` rep 1, baseline
  delivered no code): **17–4** among pairs with code on both sides.
  v0.4.0: 14–8.
- **ponytail vs total-programming: 15–8** (mean 3.75 vs 3.21); every pair
  had code on both sides. v0.4.0: 15–7.

The judge's comments keep naming the same contrast as in v0.4.0: single
readable components with plain state (Total Programming and, more
aggressively, ponytail) versus context-provider registrations and dense
math spread across files (baseline). Ponytail still wins the head-to-head
on the feature tasks it compresses hardest.

## What changed vs v0.4.0 wording

1. **LOC effect unchanged** (79% vs 78%): the reframe of Clarity,
   Atomicity, and Asymmetry did not make the arm build less.
2. **Token/time overhead flipped** from +3% tokens / slower wall to
   −10% tokens / −20% wall — the clearest measurable difference between
   the wordings, consistent with "focus where it matters" replacing
   uniform care.
3. **Correctness/safety**: the TP arm is now perfect across all 228
   scored checks; baseline regressed slightly on `cache` (2 of 4 reps
   scored as over-engineering).
4. **Judge preference widened** from 14–8 to 18–4 (17–4 excluding the
   walkover). The ponytail head-to-head is stable (15–7 → 15–8).

These are single-run observational comparisons across wordings measured on
different days; only the within-run arm comparisons are controlled.

## Caveats

- Single run, single model (GLM 5.3 Flash through the pi harness), single
  judge model (Sonnet). No paired significance tests.
- The judge covers the 6 front-end feature tasks only (24 pairs per
  comparison); `prefer` is positional and wins are derived via the recorded
  arm assignment.
- Arms are comparable within the run (same fixture, prompts, seeds,
  scorers). Cross-wording comparisons (v0.4.0 vs v0.5.0) are observational.
- Scorer quirks noted where relevant (`sql-user`); no score was manually
  adjusted.
