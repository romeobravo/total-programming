# Benchmark results — 2026-09-25, Haiku 4.5 (v0.4.0 wording)

Clean Claude Code baseline vs. the eleven Total Programming principles, using
Ponytail's pinned agentic benchmark (`e3ba2aa`) on the FastAPI template (`cd83fc1`).
Both arms ran with `--safe-mode`, no user configuration, no plugins, no skills, and
file tools only. The treatment appended the canonical principles to the system
prompt; the baseline received nothing. 19 tasks × 2 arms × 4 repetitions = 152
sessions; 152 completed, none hit the 300-second timeout. Total reported list-price
cost: $9.26. Claude Code CLI pinned to 2.1.277 (the release current for the earlier
run; 2.1.282+ injects two builtin plugins into every session init, which the
isolation check rejects). Principles commit `ee24ba2` (the v0.4.0 merge: Dutch
1-4-3-3 numbering and the six refined headings), skill SHA-256 `2139cc74ee87…`.
Full raw evidence: `benchmarks/runs/2026-09-25-v04-haiku/` (gitignored; see
`benchmarks/README.md`).

## Complexity (post-hoc, deterministic)

Cyclomatic complexity (lizard 1.24.0) over delivered source files (tests excluded), median
per task, mean over tasks. `benchmarks/complexity.py`; no model calls. All three arms were
(re)computed with this single lizard version over the same run evidence — the Ponytail arm
including its retry runs — so the rows are mutually consistent; small deltas versus the
initial post-hoc stem from that recomputation.

The Ponytail arm was run separately under the same harness, CLI, fixture and model with its own
SKILL.md appended the same way. In the first attempt 55 of 76 cells produced a valid run (21 hit
the 300-second cap). The 21 timed-out cells were then independently retried under the identical
conditions; all 21 completed within the cap (see "Ponytail timeout retry" below). The tables show
the pooled runs, n=4 per task.

Reading: Total Programming delivers less code by **building less**, not by writing
denser functions — per-function complexity is flat versus the baseline on the
feature tier and roughly 35% lower on the safety tier (the `critic-email` judge
case: baseline CC 15 → TP 6). Ponytail delivers the smallest and structurally
simplest code, at similar cost per run but roughly double the wall time on the
feature tier, and its ladder did not finish inside the 300-second cap on 21 of 76
first-attempt cells; all 21 completed on an independent retry (below).

## Ponytail timeout retry

After the tables above were first computed, the 21 cells that hit the 300-second
cap (14 feature, 7 safety) were retried once under identical conditions: same
pinned CLI (2.1.277), model, fixture, prompts, $0.75 list-price budget and
300-second cap, isolated workspaces, fresh sessions. Result: **21/21 completed,
0 timeouts**, and the 7 retried safety cells all passed their checks (7/7 safe).

First-attempt completion therefore stands at 55/76 (72%); the retry shows no task
is impossible within the cap. Reading: per-cell variance, not structural
incompleteness — but a retry cannot erase the first attempt. A fresh Ponytail run
should still be expected to hit the cap on some cells (21/76 in attempt 1; the
21/21 retry success is consistent with plain per-cell variance and cannot pin the
per-cell timeout probability more precisely at this n).

Evidence: attempt-1 timeout workspaces, the pre-retry `results.json` and the
attempt-1 `complexity.json` are preserved in
`benchmarks/runs/2026-09-25-v04-haiku-ponytail-attempt1-timeouts/`. The pooled run
lives in `benchmarks/runs/2026-09-25-v04-haiku-ponytail/` — attempt-1 valid runs
kept untouched, retries appended via `run.py --resume`. The tables above use the
pooled runs (n=4 per task).

A blind pairwise judge (`benchmarks/judge_readability.py`): for the six frontend
feature tasks, each baseline repetition was paired with the same Total Programming
repetition and scored by Claude Sonnet 4.6 via the CLI, anonymous, with the A/B
order alternating per repetition to balance position bias. 24 pairs, 24 valid:

- Preference: **Total Programming 16 — baseline 8**, no ties; mean score 3.58 vs 3.12.
- Per task: colorpicker 4–0 and rating 4–0 for TP, dropzone 3–1 and datepicker
  3–1 for TP, command 2–2, wizard 1–3 for the baseline.
- The wizard loss matches the complexity data (TP's wizard carried the most
  complex function of the run, CC 13.5). Directional evidence from a single
  judge model and single run — not a deterministic measurement.

## Interpretation and limits

- Feature-tier "correct=1" only means code was delivered; feature completeness was
  not machine-verified. Spot checks show TP runs delivering small, single-purpose
  components (e.g. a 22-line color picker wrapping the native
  `<input type="color">`; this run's date picker used a lightweight custom
  wrapper rather than Radix). The reduction is judgment-driven, not rule-driven.
- n=4 on one model (Haiku 4.5) with one seed order; treat percentages as
  directional, not precise. Dollar figures are CLI-reported list price, not
  subscription charges.
- Lower LOC is not itself the goal of the principles; this benchmark cannot
  measure maintainability or sustained pace. It shows the principles steer a
  coding agent toward materially smaller deliveries at lower cost and latency
  without dropping deterministic safety checks.
