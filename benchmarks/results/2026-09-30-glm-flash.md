# GLM 5.3 Flash — pi harness (2026-09-30)

Third arm benchmark on a much stronger model tier than the Haiku runs:
GLM 5.3 Flash served through Z.ai's coding-plan endpoint, executed by the
pi coding agent harness (`--runner pi`, `--provider zai-coding`) instead of
the Claude Code CLI. 228 cells = 19 tasks × 3 arms (baseline,
total-programming, ponytail) × 4 repetitions. Attempt 1 ran a 300 s
per-cell cap; the 54 cells that timed out were re-run once at 600 s and
pooled into this dataset. Per project owner decision (2026-09-29), timeout
rates are **not** analysed — no fair cap is knowable; timed-out cells
simply contribute no deliverable.

Harness note: the pi runner now caps a cell's `_pi_events.jsonl` at 256 MB
(one cell streamed 400–600 MB and OOM-killed the host twice before the
guard). Cells killed by the guard are scored as timeouts.

## Delivery (valid runs at the 600 s cap)

| arm | delivered | correct | safe |
|---|---|---|---|
| baseline | 63/76 | 62/63 | 63/63 |
| total-programming | 59/76 | 59/59 | 59/59 |
| ponytail | 76/76 | 76/76 | 76/76 |

Total Programming had no valid delivery on any repetition of the three
largest feature tasks (colorpicker, command, wizard — 222/415/481 baseline
LOC), which is why paired comparisons below cover 16 of 19 tasks.

## Delivered LOC (paired per task, median per repetition set)

| arm | geometric mean vs baseline | n tasks |
|---|---|---|
| total-programming | 85% | 16 |
| ponytail | 46% | 19 |

Contrast with the Haiku runs, where Total Programming cut 43%. The much
stronger baseline arrives lean already; the marginal cut shrinks to ~15%.
Total Programming ≈ ponytail on absolute size for the tasks it delivered
(mean 47 vs 45 LOC).

## Cyclomatic complexity (lizard, common cohort)

Same 16 tasks for every arm (Total Programming's delivered cohort), mean
of per-task medians per function:

| arm | feature: n_fn | feature: cc mean / max | safety: cc mean / max |
|---|---|---|---|
| baseline | 10.6 | 2.94 / 5.6 | 5.11 / 5.9 |
| total-programming | 12.6 | 2.71 / 5.0 | 3.52 / 4.1 |
| ponytail | 6.6 | 2.39 / 3.4 | 2.25 / 2.6 |

The Haiku pattern replicates qualitatively and weaker: per-function
complexity ≈ baseline on features (−8%), ~31% lower on safety tasks.
Ponytail is structurally simplest everywhere (no function above CC 5).

## Blind readability judge (Sonnet, anonymous A/B, position-balanced)

Pairs score both solutions 1–5 and pick a preference; only pairs with
source on both sides are counted.

- **Total Programming vs baseline: 7–6 for baseline** (14 pairs, 1 tie; 10
  further pairs excluded because Total Programming delivered no source).
  On Haiku this was 16–8 for Total Programming — the edge is gone at this
  model tier.
- **Ponytail vs Total Programming: 20–4 for ponytail** (24 pairs, 0 ties).
  On Haiku this was 14–7.

## Reading

On a model that is already lean and clean by default, principle steering
buys much less: smaller relative cuts, no readability edge, and — the
notable negative — no valid delivery on the three largest UI tasks within
the cap. The mechanical minimalism of ponytail, by contrast, completed
every cell, delivered the smallest and structurally simplest code, and won
the blind head-to-head decisively. This runs counter to the expectation
that judgment-first prompting would scale better with model capability.

Caveats: single run, single model, one judge model (Sonnet); the Haiku
runs used the Claude Code harness so Haiku-vs-GLM differences conflate
model tier with harness; ponytail's skill text was appended raw including
its YAML frontmatter (same method as the Haiku run, so arms are comparable
within the run).
