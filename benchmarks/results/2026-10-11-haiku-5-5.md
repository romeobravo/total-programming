# Claude Haiku 5.5 — claude CLI harness, complete dataset (2026-10-11)

Report for the 2026-10-11 Claude Haiku 5.5 run (`--runner claude
--model-id claude-haiku-5-5`): 228 cells = 19 tasks × 3 arms (baseline,
total-programming, ponytail) × 4 repetitions. All 228 cells delivered
first-attempt — no timeouts, no failures, no retries. This is the first
three-arm run on the claude CLI harness and the first run on a second
model family since the 0.4 Haiku 4.5 arm-pair (baseline ×
total-programming only, never judged).

Setup: claude CLI pinned at 2.1.277, ponytail upstream pinned at
`e3ba2aa`, fastapi fixture pinned at `cd83fc1`, SKILL.md pinned at
`07e31a3e…` — byte-identical to the wording measured in the GLM 5.3
Flash 0.5 run, so the cross-model comparison of the skill arms is
wording-controlled. Workers 2, per-cell timeout 1200 s (no cell came
near it). Total list-price cost **$34.25** (median $0.10–$0.18 per cell
by arm; every cell under the $0.75 cap).

One manifest nit: with `--model-id` the runner appends a stale
adaptation string claiming cells run "via ANTHROPIC_BASE_URL to a
compatible endpoint; CLI-reported cost is not Anthropic list price
here". That dates from the dead GLM-through-claude route; this run went
first-party Anthropic and all costs are CLI-reported list price.

## Cross-model comparison (same SKILL.md pin)

| comparison | GLM 5.3 Flash 0.5 (pi) | Haiku 5.5 (claude) |
|---|---|---|
| TP vs baseline, CPO | **13** – 10 TP | 5 – **18** baseline |
| TP vs ponytail, CPO | **17** – 7 TP | **16** – 8 TP |
| baseline vs ponytail, CPO | not run | **19** – 4 baseline |
| TP vs baseline, readability | **18** – 4 TP | 8 – **10** baseline |
| TP vs ponytail, readability | 8 – **15** ponytail | 9 – **14** ponytail |

Two results replicate across models: Total Programming beats ponytail
on the CPO product lens (16–8 here vs 17–7 on GLM), and ponytail leads
the narrow readability lens. The baseline comparison flips entirely: on
GLM the skills beat the baseline on both lenses; on Haiku 5.5 the
baseline beats both skill arms on the product lens and edges TP on
readability. Appended principles are therefore strongly
model-dependent in value: Haiku 5.5's unassisted baseline already
produces product-grade code on these tasks, and neither SKILL.md nor
ponytail's improves on it there — while both still cut LOC, tokens,
wall time and cyclomatic complexity substantially.

## Limits

- Single run, single model, sonnet as the judge for both lenses.
- Harness conflation on cross-model rows: GLM ran via the pi harness,
  Haiku via the claude CLI (each model's native route); prompt-plumbing
  differs beyond the pinned SKILL.md wording.
- Readability tallies exclude 8 transient judge parse failures out of
  72 pairs; CPO is 72/72. No pair was a walkover.
- The uniform cache-task misses are the scorer's over-engineering axis,
  identical across arms; on this model all three profiles over-build on
  that trap.
